<objective>
Refactor AWS Network Mapper so the codebase is readable because ownership is clear, not because long functions were merely rewrapped.

Purpose: the formatting pass made the files easier to scan, but it did not change the architecture. The app still depends on a very large plain-script orchestrator, DOM-coupled exports, mixed UI/business engines, and several parallel rendering paths that must be kept in sync by memory. This plan turns that into a sequence of behavior-preserving refactors with tests around each risky seam.

Output:
- A smaller `src/app-core.js` that delegates cohesive behavior to named modules.
- Engine modules organized around data predicates, rule definitions, and finding/result factories.
- Renderer, report, export, and UI modules that accept explicit context/options instead of ambient globals where practical.
- Characterization tests and E2E coverage strong enough to make later cleanup boring.
- A branch that keeps generated output and public docs clean.
</objective>

<interfaces>
The current browser app has three load surfaces that must remain stable during the refactor:

1. `src/main.js` is bundled to `dist/app.bundle.js` as an IIFE and populates `window.AppModules`.
2. `src/exports/index.js` is bundled to `dist/core.bundle.js` and populates `window._core`.
3. `src/app-core.js` remains a plain script. It cannot use ES imports directly unless the build and HTML loading strategy change.

`build.js` currently bundles `src/main.js`, bundles `src/exports/index.js`, then copies or minifies `src/app-core.js`. Do not hand-edit `dist/*`; change source and rebuild.

The main render context is still named `_rlCtx` in app-core and in several extracted modules. Treat `_rlCtx`, `_mapSvg`, `_mapG`, `gwNames`, compliance findings, BUDR findings, imported report data, loaded account contexts, and report state as migration targets. Add a facade first, migrate call sites second, and remove globals only after tests prove no active script path depends on them.

The critical rendering paths from AGENTS.md are in:
- `src/modules/topology-renderer.js`
- `src/app-core.js` hub-spoke landing-zone layout around `renderLandingZoneMap`
- `src/app-core.js` grid/executive rendering around `_renderMapInner`
- `src/modules/landing.js`

Exports split across `src/modules/report-html.js`, `src/modules/export-utils.js`, and `src/exports/*`. Several export modules still read DOM or globals at call time. The refactor should move them toward `generateX(ctx, options, services)` while keeping `window._core` wrappers as compatibility shims.

Existing verification commands:
- `npm run format:check`
- `npm run test:unit`
- `npm run test`
- `npm run bundle:prod`
</interfaces>
