- 32 JavaScript files.

- 7 are currently not imported by `src/main.js`: `dashboards.js`, `detail-panel.js`, `firewall-engine.js`, `landing.js`, `notes.js`, `search.js`, and `topology-renderer.js`.

  - Engines: `cidr-engine.js`, `network-rules.js`, `compliance-engine.js`, `budr-engine.js`, `iam-engine.js`, `dep-graph.js`.
  - Feature modules: `design-mode.js`, `flow-tracing.js`, `flow-analysis.js`, `firewall-editor.js`, `multi-account.js`.
  - Views and reports: `compliance-view.js`, `unified-dashboard.js`, `governance.js`, `export-utils.js`, `iac-generator.js`, `report-html.js`.

**`src/exports/`**
- 9 JavaScript files.
- `index.js` exposes all consumed exports on `window._core`.
- Format generators: `exports-iac.js`, `exports-visio.js`, `exports-lucid.js`, `exports-scripts.js`, `exports-docx.js`, `exports-xlsx.js`.

**`dist/`**
- Generated by `build.js`, but tracked and required by runtime.
- `dist/app.bundle.js` comes from `src/main.js`.
- `dist/core.bundle.js` comes from `src/exports/index.js`.
- `dist/app-core.js` comes from `src/app-core.js`.
- `dist/edge-tests.js` is dev-only and removed by production build.

**`libs/`**
- `d3.custom.min.js` is generated from `src/d3-custom.js`.
- `jszip.min.js` and `xlsx.bundle.min.js` are vendored.
- `libs/fonts/` contains bundled IBM Plex font files.

**`tests/`**
- 7 Playwright specs in `tests/*.spec.js`.
- 12 unit test files in `tests/unit/*.test.mjs`.
- `tests/helpers.js` centralizes demo loading, dashboard opening, SVG click dispatch, and console error capture.
- Visual baselines are stored under `tests/visual.spec.js-snapshots/`.

## Naming Conventions

**Files:**
- Kebab-case for modules and tests, such as `compliance-engine.js`, `export-utils.js`, and `network-rules.test.mjs`.
- `exports-*` prefix for format-specific export modules.
- Root Electron files remain conventional names: `main.js` and `preload.js`.

**Functions and State:**
- Many legacy app-core functions use underscore prefixes, such as `_renderMapInner`, `_renderCompDash`, `_saveSnapshots`, and `_exportDiffReport`.
- Extracted modules often expose named functions plus getter/setter pairs for migrated state.
- Transitional globals use names such as `window.AppModules`, `window._core`, and `window._complianceFindings`.

**Tests:**
- Unit files mirror source module names: `cidr-engine.test.mjs`, `network-rules.test.mjs`, `export-utils.test.mjs`.
- E2E specs are workflow/feature oriented: `smoke.spec.js`, `dashboard.spec.js`, `export.spec.js`.

## Where To Add Code

**New pure logic:**
- Prefer a named ES module under `src/modules/`.
- Import it in `src/main.js` if runtime needs it through `window.AppModules`.
- Add a unit test under `tests/unit/`.

**New export format or export helper:**
- Add to `src/exports/exports-{format}.js`.
- Re-export through `src/exports/index.js` on `window._core`.
- Add unit coverage where the logic can run without DOM.

**New Electron capability:**
- Add IPC handler in `main.js`.
- Expose a constrained wrapper in `preload.js`.
- Consume through `window.electronAPI`.

**New UI workflow:**
- If it is DOM-heavy and coupled to existing panels, current pattern is still `src/app-core.js`.
- If logic is pure or reusable, extract the non-DOM pieces first and bridge them through `src/main.js`.

**New test:**
- Unit test: `tests/unit/{module}.test.mjs`.
- E2E test: `tests/{feature}.spec.js`.
- Shared browser helper: `tests/helpers.js`.
